## What this is
A **Safari Web Extension** ("Recipe Catcher") that strips a recipe page down to a clean,
readable reader (ingredients + instructions), with metric/imperial conversion, a servings
scaler, a tickable shopping list, estimated nutrition, dark mode, and an on-page "Catch
this recipe?" prompt. Manifest V3, no network calls, all local.

- **Project root:** `~/recipe-catcher` (its own git repo; separate from the unrelated
  `~/auraluna` Flutter app — do NOT put extension work in auraluna).
- **Source of truth:** `extension/` (hand-authored WebExtension files).
- **Xcode project:** `Recipe Catcher/Recipe Catcher.xcodeproj` (generated by Apple's
  `safari-web-extension-converter`; macOS + iOS app+extension targets).
- **Bundle IDs:** app `com.rodgers.recipecatcher`, extension
  `com.rodgers.recipecatcher.Extension`.
- **Permissions (final, minimized):** `scripting`, `storage`, host `<all_urls>`.
  (`tabs` was intentionally dropped; `<all_urls>` covers active-tab URL reads.)
- **Toolchain on this Mac:** Xcode 26.6, Swift 6.3. **`node` is NOT installed** — tests
  run under macOS's built-in JavaScriptCore (`jsc`). No SVG rasterizer except `qlmanage`.

## Gotchas learned (important — save future-me time)
1. **`build-xcode.sh` regenerates the Xcode project with `--force`, which WIPES the signing
   Team** (DEVELOPMENT_TEAM → empty). For code updates, use **`sync-extension.sh`** (copies
   `extension/` into `Recipe Catcher/Shared (Extension)/Resources` in place, signing
   untouched). Only run `build-xcode.sh` when you truly need to regenerate the project, and
   expect to re-select the Team on both iOS targets afterward.
2. **Duplicate Safari extension entries** come from multiple registered app copies in
   Launch Services (dist/ + build/DerivedData/ + any scratch xcodebuild). `build-app.sh`
   now unregisters the build-folder copy and registers only `dist/`. If duplicates recur,
   `lsregister -u` the stale paths. (An iOS `Debug-iphoneos` build in `~/Library/Developer/
   Xcode/DerivedData` is a *different platform* and does NOT create a macOS Safari entry.)
3. **Temperature degree marks vary by site** — many use `º` (U+00BA ordinal), not `°`
   (U+00B0). `convertTemperatures` in `extension/units.js` handles `°/º/˚/℉/℃`; keep that
   if refactoring. Test recipe that exposed it: Preppy Kitchen macarons (`270ºF`).
4. **qlmanage renders SVG into a SQUARE and fills by width** (clips height). The screenshot
   generator works around this by authoring on a **square canvas** (content centered) then
   **cropping the center** with `sips -c H W`. Pipeline per file:
   `qlmanage -t -s <max(W,H)> -o png f.svg` then `sips -c H W png/f.svg.png --out out.png`.
   Also: `qlmanage` uses system fonts; there's no other rasterizer installed.
5. **No `node`** on this Mac → use `jsc` at
   `/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc`.
6. **Reader escapes all recipe-derived strings** (`esc()` in `reader.js`) — keep that; the
   reader is a privileged extension page and recipe data comes from arbitrary web pages.
